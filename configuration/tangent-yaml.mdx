---
title: "Overview"
description: "One config file describes a whole pipeline: its runtime, sources, plugins, inference nodes, sinks, and the DAG between them."
---

A pipeline is **one config**, usually called `tangent.yaml`. `tangent run`, `tangent plugin compile`, `tangent plugin test`, `tangent bench`, and `tangent config` all take it with `--config`.

The config can span several files: [`include:`](/configuration/include) merges other files into it. A [pack](/packs/overview) is a file you include, for example.

---

## Minimal example

This is the config `tangent plugin scaffold` writes:

```yaml tangent.yaml icon=settings
runtime:
  plugins_path: "plugins/"
plugins:
  hellologs:
    module_type: python
    path: mapper.py
    tests:
      - input: tests/input.json
        expected: tests/expected.json
sources:
  network_input:
    type: tcp
    bind_address: 0.0.0.0:9000
sinks:
  blackhole:
    type: blackhole
dag:
  - from: network_input
    to: [hellologs]
  - from: hellologs
    to: [blackhole]
```

## Top-level keys

| key | what it holds | page |
|---|---|---|
| `include` | other files merged into this one | [Include](/configuration/include) |
| `runtime` | batching, workers, where compiled plugins live, the state store | [Runtime](/configuration/runtime) |
| `sources` | where records come from | [Sources](/configuration/sources/overview) |
| `plugins` | WASM plugins: language, source path, tests, grouping | [Plugins](/configuration/plugins) |
| `inference` | nodes that ask a model about each record | [Inference](/configuration/inference) |
| `enrichment_tables` | reference data loaded once and shared by every plugin | [Enrichment tables](/configuration/enrichment-tables) |
| `sinks` | where records go | [Sinks](/configuration/sinks/overview) |
| `dag` | the edges between nodes, by name | [DAG](/configuration/dag) |

Every key is optional. `runtime` falls back to its defaults when it's left out.

---

## Rules that hold everywhere

* **A name is one node.** Sources, plugins, inference nodes, and sinks share one namespace, so the DAG can refer to each by name alone. A config where two nodes share a name fails to load.
* **Unknown keys are errors**, at the top level and inside a block. A misspelling like `includes:` or `bind_adress` stops the load instead of being ignored. A top-level key that starts with `x-` belongs to the file itself, for YAML anchors (`x-prompt: &prompt judge.md`), and is ignored by tangent.
* **`${VAR}` is expanded** in every file, including `include` paths. `${VAR:-default}` uses `default` when the variable is unset or empty.

To see the config the way the runtime reads it, with its includes merged, `${VAR}` expanded, and every default filled in, run [`tangent config`](/cli/config).
