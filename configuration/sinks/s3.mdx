title: "S3"
description: "Write processed records to an Amazon S3 bucket."

The **S3 sink** uploads objects to S3, with durability from a local **write-ahead log (WAL)**. Encoding, compression, and object size use the [common sink options](/configuration/sinks/overview#common-configuration).

---

## Schema

<ParamField path="type" type="string" required>
Must be `s3`.
</ParamField>

<ParamField path="bucket_name" type="string" required>
Name of the destination S3 bucket, without an `s3://` prefix.
</ParamField>

<ParamField path="key_prefix" type="string">
What each object's key starts with, before a `/` and the object's name. It's a strftime template, rendered in UTC when a write reaches the sink, as a [rolling file](/configuration/sinks/rolling-file) sink's `path` is, so `logs/cloudtrail/%Y/%m/%d` puts each day's objects under a prefix of their own (`%%` is a `%`). An object holds the records written that day, whatever times they carry, so a replay of last week's logs goes under today's date. Without a `key_prefix`, objects go to the bucket's root.

It's a path in the bucket, and strftime is all that's rendered. `tangent run` and `tangent config` refuse a `key_prefix` that isn't a strftime template, holds a `{{ field }}`, starts with `/`, or has an empty (`//`), `.`, or `..` segment. A trailing `/` is fine: the key still has one `/` before the name. Quote a `key_prefix` that starts with `%`, as `key_prefix: "%Y/%m/%d"`, because YAML can't start an unquoted value with `%`.
</ParamField>

<ParamField path="region" type="string">
AWS region of the bucket. If it's omitted, the AWS SDK's default resolution applies (environment variables, instance metadata, and so on).
</ParamField>

<ParamField path="wal_path" type="string">
Directory for the sink's write-ahead log. Defaults to `/tmp/wal`.
</ParamField>

<ParamField path="max_file_age_seconds" type="int">
Longest time, in seconds, a WAL file stays open before it's sealed and uploaded. Defaults to `60`.
</ParamField>

<ParamField path="encoding" type="object">
How records are serialized. See [Encoding](/configuration/sinks/encoding).
</ParamField>

<ParamField path="compression" type="object">
How encoded objects are compressed. See [Compression](/configuration/sinks/compression).
</ParamField>

## Example (NDJSON + Zstd)

```yaml tangent.yaml icon=upload
sinks:
  s3_staging:
    type: s3
    bucket_name: my-bucket
    region: us-west-2
    encoding:                # the default, shown explicitly
      type: ndjson
    compression:             # the default, shown explicitly
      type: zstd
      level: 3
    wal_path: /tmp/wal
    max_file_age_seconds: 60
```

## Example (Parquet + Gzip)

```yaml tangent.yaml icon=upload
sinks:
  s3_parquet:
    type: s3
    bucket_name: analytics-data
    region: us-east-1
    encoding:
      type: parquet
      record_column: record
      schema:
        ts: timestamp
        source: string
        _norm: { org: string, actor: string }
    compression:
      type: gzip
      level: 6
    wal_path: /var/lib/tangent/wal
    max_file_age_seconds: 120
```

## Example (a prefix per day)

```yaml tangent.yaml icon=upload
sinks:
  archive:
    type: s3
    bucket_name: acme-logs
    key_prefix: logs/cloudtrail/%Y/%m/%d   # logs/cloudtrail/2026/11/06/<ULID>.ndjson.zst
    wal_path: /var/lib/tangent/wal
```

## Durability and delivery

* **At-least-once delivery**: records are appended to the local WAL, and a write is acked once it's there.
* A WAL file is sealed by **size** (`object_max_bytes`) or **age** (`max_file_age_seconds`), then encoded and uploaded as one object.
* Objects are named by a ULID, which sorts by time, plus the encoding's extension: for example `<ULID>.ndjson.zst` or `<ULID>.parquet`. An object's key is its rendered `key_prefix`, a `/`, and that name, as `logs/cloudtrail/2026/11/06/<ULID>.ndjson.zst`; without a `key_prefix`, the key is the name alone.
* Each rendered prefix has a WAL file of its own, so an object never holds records from two prefixes. When the day turns in UTC, a `%d` prefix's writes start a new file, and the day before's is sealed by size or age as usual.
* On restart, WAL files left open are sealed and uploaded, cut back to their last whole line. Each goes under the prefix rendered when it was written, even if the day has turned or `key_prefix` has changed since.
