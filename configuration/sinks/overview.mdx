---
title: "Overview"
description: "Write processed records to storage, or discard them."
---

Sinks define **where Tangent writes data**: S3 buckets, files and directories, a SQLite table, Slack, or nowhere at all. They're the **terminal nodes** of the DAG: an edge can end at a sink, and none can leave one.

---

## Sink types

| Type | Writes | Docs |
|------|--------|------|
| `s3` | objects in an Amazon S3 bucket, through a local WAL | [S3](/configuration/sinks/s3) |
| `rolling_file` | whole files in a directory, for a query engine to read | [Rolling file](/configuration/sinks/rolling-file) |
| `file` | NDJSON appended to one file | [File](/configuration/sinks/file) |
| `blackhole` | nothing: records are discarded | [Blackhole](/configuration/sinks/blackhole) |
| `sqlite` | rows in a SQLite table, with an index per partition | [README](https://github.com/EthanBlackburn/tangent#keeping-records-and-reading-them-back) |
| `slack` | one Slack message per record, through an incoming webhook | [packs/core](https://github.com/EthanBlackburn/tangent/tree/main/packs/core#slack) |

---

## Common configuration

<ParamField path="type" type="string" required>
Selects the sink type, from the table above.
</ParamField>

<ParamField path="encoding" type="object">
How records are serialized before they're written. Defaults to `{ type: ndjson }`. See [Encoding](/configuration/sinks/encoding).
</ParamField>

<ParamField path="compression" type="object">
How encoded data is compressed. Defaults to `{ type: zstd, level: 3 }`. See [Compression](/configuration/sinks/compression).
</ParamField>

<ParamField path="object_max_bytes" type="int">
For `s3` and `rolling_file`, the size of records at which a WAL file is sealed and becomes an object or file. Defaults to `134217728` (128 MiB).
</ParamField>

<ParamField path="in_flight_limit" type="int">
Writes in flight to this sink at once. Defaults to `16`.
</ParamField>

---

## Example (S3 sink)

```yaml tangent.yaml icon=upload
sinks:
  s3_main:
    type: s3
    bucket_name: my-bucket
    region: us-west-2
    encoding:
      type: parquet
      schema:
        ts: timestamp
        message: string
    compression:
      type: gzip
      level: 6
```

---

## Behavior

* The `s3` and `rolling_file` sinks each keep a write-ahead log (WAL). A write is acked once it's in the WAL, and a WAL file is sealed by size (`object_max_bytes`) or age (`max_file_age_seconds`), then written out whole.
* Encoding and compression happen when a sealed file is written out.
* A sink's name can't also name a source, plugin, or inference node.
