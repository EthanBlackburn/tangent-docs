---
title: "SQS"
description: "Ingest messages from an Amazon SQS queue, or the S3 objects its notifications name."
---

The **SQS source** consumes messages from an Amazon Simple Queue Service (SQS) queue. A message can carry records itself, or be an S3 event notification, in which case Tangent reads the objects it names.

---

## Schema

<ParamField path="type" type="string" required>
Must be `sqs`.
</ParamField>

<ParamField path="queue_url" type="string" required>
The full URL of the SQS queue to poll, such as `https://sqs.us-east-1.amazonaws.com/123456789012/my-queue`.
</ParamField>

<ParamField path="decoding" type="object" required>
How to parse a message body, or an S3 object's bytes. See [Decoding](/configuration/sources/decoding).
</ParamField>

<ParamField path="wait_time_seconds" type="int">
Long-polling duration in seconds: how long Tangent waits for messages before an empty response. Defaults to `20`.
</ParamField>

<ParamField path="visibility_timeout" type="int">
How long, in seconds, a message stays invisible to other consumers after Tangent receives it. Defaults to `60`.
</ParamField>

---

## Example

```yaml tangent.yaml icon=cloud
sources:
  sqs_logs:
    type: sqs
    queue_url: "https://sqs.us-east-1.amazonaws.com/123456789012/app-logs"
    wait_time_seconds: 20
    visibility_timeout: 60
    decoding:
      format: { type: json }
      compression: { type: auto }
```

---

## Behavior

* Tangent long-polls the queue with the AWS SDK and its default credential chain.
* When a message body is an S3 event notification (a `Records` list naming `s3.bucket.name` and `s3.object.key`), Tangent reads each object and decodes it. With `compression: { type: auto }`, the object's `Content-Encoding`, its key's suffix, or its magic bytes say whether it's compressed.
* Otherwise, the message body itself is decoded.
* A message is deleted once its records are through the pipeline. A message that isn't deleted before its visibility timeout is delivered again.

---

## Best practices

* **Keep `wait_time_seconds` high (for example, 20)** to reduce API calls and costs.
* **Give Tangent's credentials** `sqs:ReceiveMessage` and `sqs:DeleteMessage` on the queue, and `s3:GetObject` on the buckets its notifications name.
* **Set `visibility_timeout`** longer than your typical processing time, so messages aren't delivered twice.
