A **pack** is what tangent knows about one provider's logs. It's one plugin, named after the provider. Tangent's own sources read the logs, and the pack's plugin turns each raw record into a finished one:

1. It drops the keys only the pipeline writes (`_norm`, `_facts`, `_ip`, `_context`, `_baseline`), so a log line can't speak for it.
2. It normalizes the record: `_norm` says who did what, from where, to what (`actor`, `person`, `org`, `kind`, `ip`, `country`, `dest`, `target`), the same way for every provider.
3. It strips what's redundant or never decides a verdict: per-event ids, hashes, pagination, issued credentials, URL signatures.
4. It enriches the record's address from the [enrichment tables](/configuration/enrichment-tables): country, network and owner, hosting provider, Tor exit, VPN.
5. It adds, under `_facts`, what your company profile says about the record, and what only that provider's log can say.

| pack | takes `source` | from |
|---|---|---|
| [aws](https://github.com/EthanBlackburn/tangent/tree/main/packs/aws) | `cloudtrail` | the `cloudtrail` source: a trail's files, every account of an organization trail |
| [github](https://github.com/EthanBlackburn/tangent/tree/main/packs/github) | `github_audit`, `gha_ci`, `runner_egress` | the `github_audit` source; Actions job logs and runner egress as NDJSON |
| [okta](https://github.com/EthanBlackburn/tangent/tree/main/packs/okta) | `okta` | the `okta` source: the System Log |
| [google_workspace](https://github.com/EthanBlackburn/tangent/tree/main/packs/google_workspace) | `google_workspace` | the `google_workspace` source: login, token, drive, and admin activity |
| [app](https://github.com/EthanBlackburn/tangent/tree/main/packs/app) | `app`, `agent`, and names you list | NDJSON from your product: its audit log, an AI agent's run log |

A `tcp` source takes anything else as NDJSON with a `source` field. Each pack's README lists its source's config block and credentials.

[packs/core](https://github.com/EthanBlackburn/tangent/tree/main/packs/core) isn't a provider. It's what every pack needs:

* **`ingest.yaml`**: the runtime, the enrichment tables, the `lake` sink (every finished record as Parquet, a directory per hour), and `baseline_builder`, which folds each record into the state store.
* **`judge.yaml`**: `baseline_renderer`, which groups each actor's records and adds the actor's history as `_baseline`, and the `judge` inference node, which reads each actor's records and flags bad behavior. What it flags goes to `alerts.ndjson`, and every verdict to `verdicts.ndjson`.

## Using packs

A pipeline is one config. It [includes](/configuration/include) core's `ingest.yaml` and `judge.yaml`, plus the `ingest.yaml` of each pack you want. Your part of the config names your sources, sends each source to its pack and each pack's records on to `lake`, `baseline_builder`, and the judge (`baseline_renderer`), and points the `profile` table at your company.

Each actor's records wait in a group for the judge (`baseline_renderer` has a `group_by`), and the judge runs on workers of its own, so ingest never waits on the model. To keep finished records in the lake with no model, leave out `judge.yaml` and the edges to `baseline_builder` and `baseline_renderer`.

To watch AWS and Okta from a directory beside your tangent checkout:

```yaml tangent.yaml icon=settings
include:
  - ../tangent/packs/core/ingest.yaml
  - ../tangent/packs/core/judge.yaml
  - ../tangent/packs/aws/ingest.yaml
  - ../tangent/packs/okta/ingest.yaml

enrichment_tables:
  profile: { type: document, path: profile/profile.yaml, required: true }   # your company

sources:
  cloudtrail: { type: cloudtrail, region: "${AWS_REGION}", queue_url: "${CLOUDTRAIL_QUEUE_URL}" }
  okta_audit: { type: okta, org_url: "${OKTA_ORG_URL}", token: "${OKTA_API_TOKEN}" }

dag:
  - from: cloudtrail
    to: [aws]
  - from: okta_audit
    to: [okta]
  - from: aws     # kept, learned, judged
    to: [lake, baseline_builder, baseline_renderer]
  - from: okta
    to: [lake, baseline_builder, baseline_renderer]
```

```yaml profile/profile.yaml
# what no log says about you; packs/core/README.md lists every key
org: example
own_sources: [cloudtrail, okta]      # their records are all this org's
countries: [US]
members: [alice@example.com, bob@example.com]
people: { alice@example.com: [alice] }   # one person under each name: the IAM user alice is alice@example.com
networks: [203.0.113.0/24]           # your office and VPN egress
watch: [StopLogging, user.mfa.factor.deactivate]
```

```bash
brew install gh                                   # once: it checks each prebuilt plugin's attestation; no login
../tangent/examples/enrich/setup.sh data          # once: GeoLite2, cloud ranges, Tor exits
tangent plugin fetch --config tangent.yaml        # the packs' plugins, prebuilt and attested
tangent plugin test --config tangent.yaml         # the aws and okta fixtures
tangent run --config tangent.yaml
```

<Warning>
Packs need a tangent newer than release 0.1.9, which doesn't know `include:` or `enrichment_tables` and stops at ``missing field `runtime` ``. Until the next release, build tangent from your checkout (`cargo install --path ../tangent/crates/cli --locked`), and run `tangent plugin compile --config tangent.yaml` instead of `tangent plugin fetch`: the packs' prebuilt plugins ship with tangent from the next release on.
</Warning>

`tangent plugin compile` in place of `fetch` builds the packs from source, which is also what you want for a pack you're changing. It needs the Rust WASM toolchain, which `../tangent/examples/enrich/setup.sh` (without `data`) installs.

The judge is any OpenAI-compatible model, set with `JUDGE_URL` (a local model on `:8080` by default), `JUDGE_MODEL` (`glm-4.7-flash` by default), and `JUDGE_API_KEY`. [packs/core](https://github.com/EthanBlackburn/tangent/tree/main/packs/core) lists the profile's keys and the judge's settings.

### Several packs from one source

A `tcp` source can feed several packs: route it to each, and each takes only its own `source` values. A record whose `source` no included pack takes goes no further, and `tangent run` says so. To keep records in your own shape, send them as `source: app`, or list their name under `plugins.app.config.extra_sources`.

[examples/cloud-infra](https://github.com/EthanBlackburn/tangent/tree/main/examples/cloud-infra) runs every pack for a fictional company, and [examples/app-log](https://github.com/EthanBlackburn/tangent/tree/main/examples/app-log) runs the app pack with one org per customer.

## Prebuilt plugins

A plugin is a WASM component, compiled once and run on every machine, so only a pack's author needs the toolchain. Each pack's `ingest.yaml` says where its compiled plugin is published:

```yaml packs/aws/ingest.yaml
plugins:
  aws:
    module_type: rust
    path: .                                          # the source, for `tangent plugin compile`
    prebuilt: { repo: EthanBlackburn/tangent, workflow: .github/workflows/attest-packs.yml }
```

[`tangent plugin fetch`](/cli/plugin/fetch) downloads each `prebuilt` plugin from the release and checks its build's attestation before keeping it.

## Writing a pack

1. Copy [packs/okta](https://github.com/EthanBlackburn/tangent/tree/main/packs/okta), the smallest pack, to a directory beside it under `packs/`, and rename its package and plugin. A name can't contain `-`. The plugin's `probe()` takes your `source` values and nothing else: a `source` value belongs to one pack.
2. Write `ingest.yaml`: the plugin, named after the pack, with its fixtures under `tests:` and the tables they were written against. Leave out `dag`: the config that includes the pack routes it.
3. Add a row for each of its sources to [core's judge.yaml](https://github.com/EthanBlackburn/tangent/blob/main/packs/core/judge.yaml), under `inference.judge.encoding.sources.<source>`.
4. Write `tests/input.json` from synthetic records. `make -C packs fixtures-<name>` writes `tests/expected.json` from the plugin's output; read it before committing. `make -C packs test` runs every pack's fixtures.

The [README](https://github.com/EthanBlackburn/tangent#writing-a-pack) has the full checklist, including how to ship the pack prebuilt.
